# GitHub Workflow

1. Create one private or supervisor-approved project repository.
2. Add all four members and the allocated supervisor.
3. Protect `main` if your GitHub plan permits it.
4. Each member works in a named branch.
5. Commit small, meaningful changes throughout the project.
6. Open pull requests for integration.
7. Link Jira issue IDs in commit messages where practical, e.g. `ICT942-23 add spam-risk analytics`.
8. Use pull-request review comments as teamwork evidence.
9. Tag meaningful milestones such as `assessment1-week5` and `prototype-v1.0`.
10. Keep generated runtime files such as the SQLite database out of Git using `.gitignore`.

Recommended commit style:
- `feat:` new feature
- `fix:` defect correction
- `test:` automated test
- `docs:` project documentation
- `refactor:` internal code improvement
- `data:` dataset/preprocessing change
