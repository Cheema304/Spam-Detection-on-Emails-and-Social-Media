## Assessment 3 Project Update

This section tracks the review and update of the SpamShield AI project scope, objectives and success criteria for Assessment 3. The project boundaries, constraints and expected outcomes will be reviewed against the current implemented prototype and project evidence.

## Week 1 — Project Charter and Stakeholder Analysis
Evidence to maintain:
- project title, industry partner/client, four team members, supervisor and date
- background/problem notes supported by client/research evidence
- three measurable project objectives
- explicit in-scope and out-of-scope boundaries
- stakeholder matrix with role, interest and influence
- measurable success criteria
- GitHub repository created
- Jira project created
- supervisor invited to both GitHub and Jira by end of Week 1

Project evidence already supplied:
- working repository structure
- system architecture graphic
- team-allocation plan
- Git/Jira workflow documents

## Week 2 — Business and Problem Analysis
Evidence to produce from real client/research input:
- executive summary notes
- organisation overview: sector, business model, key services/products
- current-process description
- identified challenges
- concise problem statement
- root-cause analysis
- SWOT analysis
- business-requirements summary

Do not invent organisation-specific facts. Record the actual client/supervisor evidence used.

## Week 3 — Requirements Elicitation
Evidence supplied:
- `requirements_register.csv`
- functional and non-functional requirement IDs
- requirement priorities
- stakeholder/source field ready for real evidence
- constraints and assumptions fields

Add evidence from methods actually performed, for example client discussion, observation or document review.

## Week 4 — Software Requirements Specification
Project implementation provides direct evidence for:
- proposed solution overview
- use cases
- functional requirements
- non-functional requirements
- acceptance criteria
- architecture diagram
- API interface
- validation and error paths
- requirements-to-test traceability

Use `traceability_matrix.csv` to demonstrate that requirements are testable and implemented.

## Week 5 — Feasibility and Risk Analysis
Evidence supplied:
- technical design using Python, scikit-learn, SQLite and Matplotlib
- open-source economic model
- operational workflow
- privacy/data-handling considerations
- `risk_register.csv`

- automated testing evidence

The final feasibility discussion must include your actual organisational readiness, user acceptance, budget, legal/privacy context and client-specific constraints.
